# Аудит
## Базовый образ: python:3.11.9-slim-bookworm

Что исправлено относительно исходного варианта:

Было python:3.11 — плавающий тег, указывающий на последний патч ветки 3.11 на последнем Debian. Это давало невоспроизводимость: одинаковая сборка в разное время могла дать разное содержимое образа.

Стало `python:3.11.9-slim-bookworm` — зафиксирована:
*    минорная версия Python (3.11.9),
*    вариант сборки (slim — без лишних пакетов),
*    базовая ОС (Debian 12 «bookworm»).

Это уже даёт предсказуемую версию Python и Debian-релиза, что покрывает основную проблему невоспроизводимости.

**Вывод**: в рамках задания выбран компромисс python:3.11.9-slim-bookworm — он покрывает проблему невоспроизводимости на уровне версии Python и Debian. Дальнейшее усиление — переход на digest + автоматика обновления + собственное зеркало, что выходит за рамки текущей задачи, но является логичным следующим шагом для прод-контура.

## ENV POSTGRES_PASSWORD=postgres123 в образе

**Плохо**: **ENV** фиксируется в слое образа. Даже если в следующем слое удалить переменную — пароль останется в истории.
**bash**

```bash
docker history myimage         # покажет значение
docker save myimage | tar -x   # можно вытащить из json
```

**Риск**: утёкший образ на Docker Hub / в registry = утёкший пароль БД. Даже приватный registry — это уже компромисс.

Как надо: секреты — через --env-file, Docker secrets, Vault, а не через **ENV/ARG**


## ENV DJANGO_DEBUG=1 в образе

**Плохо**: debug-режим в проде:

* показывает трассировки стека, настройки,SQL-запросы, переменные окружения (в т.ч. SECRET_KEY, пароли БД);
* отключает ряд защит (ALLOWED_HOSTS не так строг и т.д.);
* отдаёт статику через Django вместо nginx.

**Риск**: прямая утечка секретов и внутренней структуры приложения любому, кто вызовет 500-ку.

**Как надо**: DEBUG только из env, дефолт False, в проде явно 0


## apt-get install без --no-install-recommends и без чистки /var/lib/apt/lists

**Плохо**:

* `--no-install-recommends` не указан → тянутся «рекомендованные» пакеты, часто ненужные (docs, i18n, доп. утилиты);

* `/var/lib/apt/lists/*` не удалён → индекс пакетов остаётся в слое.

**Риск**: образ раздувается на сотни МБ. Медленный pull, лишние CVE, дороже storage.

**Как надо**:
```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends ... \
 && rm -rf /var/lib/apt/lists/*
```

## vim, curl в проде

**Плохо**: каждый лишний пакет — это:

* **CVE**, которые надо патчить;
*  бинарник, который может использовать атакующий (**vim** умеет :!`sh, curl` умеет **SSRF** изнутри контейнера).

**Риск**: расширение поверхности атаки. Особенно **vim** — это фактически шелл-обёртка.

**Как надо**: в проде — минимум. Отлаживать — через `kubectl debug`, `docker exe`c с отдельным образом, **ephemeral containers**.

## gcc, libpq-dev остаются в финальном образе

*Плохо**: это *build-зависимости**. Нужны только чтобы собрать Python-пакеты (psycopg2 и т.п.). В рантайме не нужны.

**Риск**:

*  образ тяжелее на ~200 МБ;
*  **gcc** в контейнере — подарок атакующему: можно скомпилировать эксплойт/майнер прямо на месте.

**Как надо**: **multi-stage build** — сборка в одном стейдже, запуск в другом (**slim/distroless**).


## COPY . . — копируется всё, включая .git, logs/, .env

**Плохо**: Эти файлы могут содержать секреты, в том числе удаленные. А также содержат мусор
и  увеличивают образ.

**Как надо**: Добавить .dockerignore

## Нет non-root пользователя

**Плохо**: процесс в контейнере = root. Если приложение скомпрометировано (**RCE** через **Django**, **uWSGI**, зависимость):

* внутри контейнера **root** может писать куда угодно;
* при неаккуратном `--privileged` или монтировании **docker.sock** — выход на хост;
* в **k8s** с **allowPrivilegeEscalation** — потенциальный escape.

**Риск**: эскалация привилегий, побег из контейнера.

**Как надо**:
```dockerfile
RUN useradd -r -u 1000 app && chown -R app /app
USER app
```

## COPY . . до pip install

**Плохо**: Docker кэширует слои. Если код скопирован раньше, чем установлены зависимости, любое изменение в коде инвалидирует слой с `pip install` - зависимости переустанавливаются каждый раз.

**Риск**: сборка 5 минут вместо 10 секунд.

Как надо:

```dockerfile

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
```

## CMD ["sh", ...] вместо ENTRYPOINT

**Плохо**: CMD легко перезаписывается при docker run image <команда>. **ENTRYPOINT** — фиксированная точка входа, аргументы идут после.

**Риск**: нельзя удобно передать доп. аргументы (`docker run image --workers 4`), а случайная команда ломает запуск.

**Как надо**:

```dockerfile
ENTRYPOINT ["/app/docker-entrypoint.sh"]
CMD ["uwsgi", "--ini", "/app/uwsgi.ini"]
```
